# 完整 SOP：用 AI 智能体 2 小时做出外贸独立站

> 整理自 [SEO小平 · seogeo.cc 原文](https://seogeo.cc/ai-agent-b2b-static-site-cloudflare-sop)（发布于 2026/07/02，更新于 2026/11/03）。
> 配套的可复制指令见 [prompts/](../prompts/README.md)，可直接开工的模板见 [template/](../template/README.md)。

---

## 第一步 · 装一个智能体

**这一步干什么**：电脑上先有一个能「动手干活」的 AI，而不是只在网页里聊天的那种。

选一个：WorkBuddy、Claude Code、ChatGPT 桌面版、DeepSeek Harness 等。装好、能正常对话即可。

> 关键区别：网页版只会告诉你「请前往官网下载 LTS 版本」，然后你自己折腾半小时；**智能体会直接把它装好**，全程你只在需要点「允许」或输密码时介入。

---

## 第二步 · 建一个空文件夹，让它进去

**这一步干什么**：给智能体划一块「工地」。它生成的所有文件都堆在这个文件夹里，你以后也在这里面找东西。别让它在桌面或 C 盘根目录里干活。

1. 在桌面新建一个文件夹，名字用**英文**，比如 `mysite`。别用中文、别带空格——中文路径会让后面一堆工具莫名报错，这是新手第一大坑。
2. 让智能体「进入」这个文件夹：
   - **有图形界面的**（WorkBuddy、ChatGPT 桌面版、DeepSeek Harness）：软件里找「选择工作目录 / 打开文件夹」，选刚建的 `mysite`。
   - **命令行的**（Claude Code）：在文件夹里打开终端——双击进入文件夹，点地址栏，删掉路径输入 `cmd` 回车（Mac：右键文件夹 → 服务 → 新建终端窗口），再在这个窗口里启动它。
3. 不确定有没有开对，问它一句：

```
你现在在哪个文件夹？把完整路径告诉我。
```

- ✅ 成功：它答出来的路径里包含 `mysite`。
- ❌ 路径不对：重新选一次目录，别将就。这一步错了，后面文件会散落在你找不到的地方。

## 第三步 · 让它把 Node.js 装好

**这一步干什么**：Node.js 是让电脑能「跑」网站代码的发动机。以前要自己去官网下载，现在直接让智能体装。

```
先帮我检查这台电脑有没有装 Node.js，版本够不够跑 Astro。
如果没装、或者版本太旧，你直接帮我装好（Windows 用 winget，Mac 用 Homebrew），

装完把版本号告诉我。全程你来操作，只有需要我点"允许"或者输密码的时候提醒我一下。
装完再帮我确认：npm 能不能正常用。
```

- ✅ 成功：「已经装好 Node v24.x.x，npm 也正常」。
- 弹窗要权限：点允许，正常。
- 它说权限不够：让它「一步步教我手动装，我照着做」。
- 它说已装过：直接进下一步。
- 云端智能体（如 Grok Bot）：本地不用装，跳过。

## 第四步 · 填 6 行基础信息

打开记事本，填这 6 行（填不出来的写「暂无」，千万别编）：

```
品牌英文名：
主要产品（写 3-6 个品类，越具体越好）：
卖给谁（哪个国家、什么类型的客户，比如"德国的户外品牌采购"）：
我的邮箱：
WhatsApp：
我最喜欢的 3 个同行网站（贴网址）：
```

**最后一行最重要。** 它决定了 AI 做出来是「能看」还是「土」。不需要说清为什么喜欢，AI 自己能看出来。

## 第五步 · 先立规矩（跳过这步后面全是返工）

### 指令（一）：把规则写成 AGENTS.md 文件

```
现在先不要写任何页面。请把我们这个项目的"隐形规则"整理成一个文件，
放在项目根目录，文件名 AGENTS.md。
这个文件的作用是：以后你每次开工前先读它，我就不用重复交代规则了。
请把这些规则写进去，用清单形式，一条一句，不要长篇解释：
【URL 规则】

只允许小写英文字母 a-z、阿拉伯数字 0-9、连字符 -
禁止大写、中文、空格、下划线、问号、等号、% 等任何特殊符号
最多三级，常规页面两级：汇总页 /模块/，详情页和分类页 /模块/名字/
不允许带日期，不允许 .html 后缀
发布后不允许修改，确需修改必须加 301 跳转

【SEO 规则】

每页 title 唯一，不超过 60 字符，包含主关键词
每页 meta description 唯一，120-158 字符
每页 canonical 自动生成绝对 URL，禁止手写
每张图片必须有描述性 alt，不许留空，不许堆关键词
每页必须有可见面包屑 + BreadcrumbList 结构化数据
结构化数据：Organization（全站一次）、WebSite、BreadcrumbList（每页）、

BlogPosting（文章）、Product（产品）、FAQPage（仅页面上真实可见的问答）
语义标签：header / nav / main / article / aside / footer，不用 div 堆布局
正文必须直接写在 HTML 里，不能靠 JS 渲染才看得见

【GEO 规则】

正文纯 HTML 可读，爬虫不执行 JS 也能拿到全部内容
品牌名、地址、认证、产能这类事实写成明确句子，不要只放在图片里
标题层级清楚，一段话说清一件事
不伪造 review 或 aggregateRating
不为 AI 发明特殊文件；llms.txt 可加，但不作为主要手段

【公用模块规则】

顶部导航、页脚全站只有一份，所有页面自动引入
任何页面都不允许自己复制一份导航或页脚
改导航只需要改一个文件

【抓取基础设施规则】

必须自己生成 404 页面（不是用服务器默认的），页面里要有返回首页和主要分类的链接
必须在 public/robots.txt 写明：允许抓取，并指向 sitemap 的完整地址
必须用 @astrojs/sitemap 在构建时自动生成 sitemap，不允许手工维护清单
以后每新增一个页面或一篇文章，重新构建后 URL 必须自动出现在 sitemap 里
sitemap 必须排除 noindex 的页面（比如 /thank-you/）
配置里的 site 必须是真实域名，否则 sitemap 里所有 URL 都是错的

写完告诉我：文件放在哪、一共写了多少条规则。
```

### 指令（二）：把公用模块建出来

```
现在按 AGENTS.md 的规则，建好全站的公用组件。先不做任何业务页面。

BaseLayout：HTML 骨架，以后所有页面都用它
Nav：顶部导航，全站唯一一份
Footer：页脚，全站唯一一份
SEOHead：接收 title / description / ogImage，
自动输出 title、meta description、canonical、Open Graph、Twitter Card
Breadcrumb：可见面包屑 + BreadcrumbList 结构化数据
seo 工具函数：生成绝对 canonical 和各类 JSON-LD

要求：

导航和页脚的链接从一份站点配置里读，不要硬编码
以后所有页面必须套 BaseLayout，不允许绕过
移动端导航用纯 CSS，不引入 JS

做完给我一张表：组件文件名 / 用途 / 需要传哪些参数。
```

### 怎么确认规则真的生效了

```
现在验证规则有没有真的生效。请随机打开 3 个页面（还没有页面就先建 3 个测试页），
逐项检查并列表告诉我：

title 是否唯一、是否 ≤60 字符
meta description 是否唯一、是否 120-158 字符
canonical 是否是绝对 URL
每张图片是否都有 alt
页面上是否有可见面包屑
源码里是否有 BreadcrumbList 和 Organization 的 JSON-LD
顶部导航和页脚是不是同一个组件引入的（不是复制粘贴的）
访问一个不存在的网址，出现的是不是我自己的 404 页面（不是服务器默认页），
页面里有没有返回首页的链接
robots.txt 能不能打开，里面有没有指向 sitemap 的完整地址
sitemap 里是不是包含了全部页面，是不是排除了 /thank-you/ 这类不该收录的页

有不符合的直接修，修完再报一遍。
```

- ✅ 成功：10 项全部通过。
- 它说「还没做」：正常，说明规则只写在文件里、没落到组件。让它现在补上。

## 第七步 · 在浏览器里打开你的网站

```
现在帮我把网站跑起来，让我在浏览器里能看到。告诉我具体要打开哪个网址。
```

它会启动本地预览，给你一个类似 `http://localhost:4321` 的地址。复制到浏览器回车。

- ✅ 成功：出现一个网页，上面写着你公司的名字。可能很朴素，但它真的出来了。把 5 个页面都点一遍。
- ❌ 打不开，按顺序排查：
  1. 跑着的窗口是不是被关了？预览服务要一直跑着。
  2. 端口被占用：说「端口 4321 被占用了，帮我换一个端口重新启动」。
  3. 都不对：把浏览器截图发给它，让它自己看。

> `localhost` 就是「你自己这台电脑」。这个网站现在只存在于你的电脑里，别人打不开、网上也搜不到。第十一步才上线。

## 第八步 · 改到你愿意发给别人看

### 改法一：说感觉，不说术语

```
我想改一下首页，我不懂术语，尽量用大白话说：
1. 最上面那块太单调了，我想看起来更有实力一点
2. 正文字有点小，特别是手机上
3. 三个产品卡片太挤
你自己判断该怎么改。改完告诉我你动了哪里。这次只改这三件，不要顺手改别的。
```

最后那句「不要顺手改别的」很重要——不然让它改字体，它可能顺便把配色也换了。

### 改法二：截图给它看（最省事）

截屏拖进对话框，配一句：

```
这是我现在的首页。先别改，告诉我最影响"专业感"的 3 个问题，按影响大小排序。
```

先诊断再决定改不改，比自己瞎猜准。

### 改法三：抄同行的版式

```
打开 [同行网址]，看它的首页结构。
告诉我它从上到下每一块讲什么，
然后按同样的顺序重排我的首页。文案用我自己的，不要抄它的文字。
```

**抄结构不抄文案**，这是最快让网站「像个正经公司」的办法。

### 改几轮算够

**三轮**：第一轮改结构（区块顺序），第二轮改视觉（大小、间距、颜色），第三轮改文案（说的是不是人话）。标准很简单：**改到「我愿意把这个链接发给朋友」就可以停。**

改完把风格锁死：

```
现在这个视觉风格我确认了。请把它整理成一份设计规范写进项目里
（颜色、字号、间距、按钮样式、卡片样式），
后面做所有新页面和模板都必须严格沿用，不要自己发挥。
```

## 第九步 · 做模板（能不能规模化扩张的关键）

### 博客模板：三件套

| 页面 | 路径 | 作用 |
|------|------|------|
| 博客首页（汇总页） | `/blog/` | 列出所有文章 + 所有分类 |
| 博客分类页 | `/blog-category/xxx/` | 列出该分类下所有文章 |
| 博客详情页 | `/blog/文章名/` | 正文 + 侧边栏 + 作者 + 上下篇 |

**博客详情页的右侧边栏，是整套设计里最关键的一环。** 规则写死：

- **上半部分**：列出**所有博客分类**，每一条都是真实可点的链接（不是 JS 菜单）。
- **下半部分**：放 **10 篇不重复的博客**，按发布时间倒序，**排除当前这一篇**。

**为什么是 10 篇？** 每一篇文章都会自动链出 10 篇。100 篇文章的站，光靠侧边栏就能产生约 1000 条内链。蜘蛛从任何一篇进来都能爬到全站——**这是纯静态站防孤岛最有效的一招。**

**强制规则**：每篇博客发布时**必须选择分类**，不选就不让发。技术做法是把分类设成「必填 + 只能从预设值里选」（schema enum 限定）。AI 漏填或瞎编分类名，构建直接报错。

**博客详情页底部两块**：

1. **作者简介**（头像 + 姓名 + 一句话背景）—— E-E-A-T 信号。
2. **上一篇 / 下一篇** —— 又一条内链。

### 发指令

```
现在做网站的模板。这是整套结构里最重要的一步，请严格按下面规则做，不要简化。
【零、URL 硬规则（最高优先级）】
全站 URL 最多三级，常规页面两级，绝对不允许出现三级以上的路径：

汇总页：/blog/、/products/、/solutions/
详情页：/blog/[文章名]/、/products/[型号]/、/solutions/[方案名]/
分类页：/blog-category/[分类]/、/product-category/[分类]/、/solution-category/[分类]/
禁止 /blog/category/xxx/ 这种三级写法。
禁止 URL 带日期、带 .html、带下划线、带中文、带大写。
产品详情页永远是 /products/[型号]/，不要写成 /products/[分类]/[型号]/。

【一、博客模板（三件套）】

/blog/ 博客首页：所有文章按发布时间倒序，带分页；页面上列出所有博客分类
/blog-category/[分类]/ 博客分类页：列出该分类下所有文章
/blog/[文章名]/ 博客详情页，必须包含：

右侧边栏上半部分：列出【所有博客分类】，每条都是真实 <a href> 链接
右侧边栏下半部分：放【最新 10 篇文章】，按发布时间倒序，
排除当前这一篇，10 篇互不重复
正文底部：作者简介（头像 + 姓名 + 一句话背景）
作者简介下方：上一篇 / 下一篇


强制分类：用 Content Collections 的 schema 把 category 设为必填，
并且只能从预设分类里选（用 enum 限定）。不填或填错，构建必须直接报错。
所有内链用真实 <a href> 标签，不要用 JS 跳转。

【二、解决方案页】
先问我：我大概会有多少个解决方案页面？

少于 20 个 → 全部放进主导航，不做分类页
多于 20 个 → 做 /solution-category/[分类]/ 分类页，导航里只放分类入口
判断完告诉我你选了哪个、为什么。

【三、产品模板（我有产品才做）】

/products/ 产品汇总页
/product-category/[分类]/ 产品分类页
/products/[型号]/ 产品详情页
产品详情页底部必须有"推荐产品"模块，放 8 个同类产品
如果我说没有产品，这部分完全跳过，不要生成任何产品页面。

【四、通用要求】

所有列表页、分类页、详情页之间的链接，必须是构建时生成的真实 HTML 链接
每个模板至少做 1 条示例内容来验证结构（1 篇示例博客、1 个示例产品）
模板里不写死具体文案，用 props 或 Content Collections 传入
做完给我一张表：模板名 / 路径 / 有几级 / 有哪些内链出口 / 需要哪些必填字段
最后自查一遍：把全站所有 URL 列出来，有没有超过三级的？有就改成扁平写法

做完运行 build，确认零报错。
```

### 别信它说「做好了」，要验证

```
模板做完了。现在帮我检查有没有孤岛页面：

列出网站所有页面，标出每一页有多少条内链指向它（inlinks）
任何 inlinks = 0 的页面，全部列出来，并告诉我该从哪个页面加链接过去
逐条确认这三件事：

每篇博客详情页的侧边栏，是不是真的有 10 条互不重复的文章链接
每篇博客是不是都归到了某个分类
每个产品详情页底部，是不是真的有 8 个推荐产品

任何超过三级的，立刻改成扁平写法，并告诉我改之前和改之后分别是什么

验证 sitemap 会自动汇总：重新 build 一次，确认 sitemap 里自动包含了
这次新增的所有模板页面（博客首页、分类页、详情页、产品页），
不需要手工添加任何一行。把 sitemap 里的 URL 总数报给我，和实际页面数对一下

有问题的直接修，修完再检查一遍。
```

- ✅ 成功：所有页面 inlinks ≥ 1，没有 0；sitemap URL 数量和实际页面数一致。
- ❌ 「有几页是 0」：让它当场加链接。一般是漏了页脚分类列表，或某分类页没被导航链到。

## 第十步 · 打包

> 打个比方——文件夹里那堆东西是**菜谱**，打包（build）是**照着菜谱把菜做出来**，出来的 `dist` 文件夹就是**端上桌的菜**。服务器要的是菜，不是菜谱。

```
现在帮我把网站打包成可以上线的版本（build）。
做完告诉我：生成的文件夹叫什么名字、在哪个位置、里面大概有多少个文件。
```

- ✅ 成功：多出 `dist` 文件夹，打包成功、无报错。
- ❌ 报错：说「打包报错了，帮我修」，它自己看日志。

> 记一下文件数量。免费版 Cloudflare 一个站最多 2 万个文件，图片特别多会撞上限。

## 第十一步 · 上线，拿到你的网址

**这一步干什么**：把 `dist` 文件夹拖到 Cloudflare 上，换回一个全世界都能打开的网址。全程不用敲命令。

1. 注册 Cloudflare：打开 `cloudflare.com`，只要邮箱和密码，不用信用卡、不用付费。注册完去邮箱点验证链接。
2. 找上传入口：左侧 **Workers & Pages** → **Create** → **Pages** → **Upload assets**（找带「上传 / Direct Upload」字样的）。
3. 起名字、拖文件夹：项目名填品牌英文名小写（如 `mybrand`），把**整个 `dist` 文件夹**拖进去。拖对了的话上传列表第一层就能看到 `index.html`。
4. 点 **Deploy site**，等十几秒。

✅ 成功：出现一个网址，如 `https://mybrand.pages.dev`。点开——这就是你的网站，全世界任何人都能打开。

**上线后顺手做一件事：确认这两个地址能打开**

- `你的域名/robots.txt`
- `你的域名/sitemap-index.xml`

两个都能打开、sitemap 里能看到页面，说明抓取基础设施没问题。别省这步——很多人直接去 Google 提交 sitemap，结果提交的是打不开的地址，白等两周。

> ⚠️ **必须知道的限制**：拖拽上传建的站以后**不能改成自动部署**（Cloudflare 官方明确说了不可逆）。认真做的话，新建一个项目改用 Git 自动部署——那一步也是让智能体带你做。

---

## 第十二步 · 绑自己的域名

> SEO/GEO 必须有正式域名。`.pages.dev` 是临时地址，正式对外一律用自有域名。

在 Cloudflare Pages 项目里进入 **Custom domains** → 添加你的域名 → 按提示在 DNS 里加一条 CNAME 记录指向 `xxx.pages.dev`。等 DNS 生效后，用自有域名打开确认正常，**再**去 Google Search Console 提交 sitemap。

## 第十三步 · 用尖叫青蛙爬一遍上线后的站

**这一步干什么**：肉眼点几页发现不了真正的坑——301 乱跳、404 死链、好几个页面共用 title、元描述空着。用 Screaming Frog SEO Spider 爬一遍，问题会排成表。

免费版一次最多爬 500 个 URL，刚上线的小站够用。

1. 打开 [screamingfrog.co.uk](https://www.screamingfrog.co.uk/seo-spider/) 下载安装。
2. 顶部地址栏填上线网址（`https://mybrand.pages.dev` 或已绑的域名），点 **Start**。
3. 跑完按下面顺序查表：

**先查状态码（Response Codes）**

- **404**：记下 URL，回头补页面或改掉指向它的链接。
- **301 / 302**：刚上线的小站，除了故意做的旧→新跳转，不该一大片跳转。莫名跳转多半是内链写错。

**再查 SEO 标题和元描述（Page Titles / Meta Description）**

- **Page Titles** → 看 **Missing**（缺 title）和 **Duplicate**（重复 title）。
- **Meta Description** → 同样看 Missing 和 Duplicate。
- 缺的补上；重复的改成每页一句不一样的话。title 和描述是 Google 在搜索结果里直接展示的东西，重复等于自己跟自己抢位置。

看不懂表，把导出结果丢给智能体：

```
我用 Screaming Frog 爬完了上线后的网站。请根据我贴上的爬取结果（或截图），按优先级列出要改的问题：

1. 404 和错误的 301/302（给出 URL 和可能原因）
2. 缺少 title / meta description 的页面
3. title 或 meta description 重复的页面（标出哪些页撞车）

每条问题告诉我：改哪个文件、改成什么样。不要编造我没贴出来的 URL。
```

- ✅ 成功：没有红一片的 404；Page Titles / Meta Description 里 Missing 和 Duplicate 都是 0。
- ❌ 爬到的全是 404：多半填成了本地 `localhost` 或旧预览地址。填 Cloudflare 上能公开打开的网址。
